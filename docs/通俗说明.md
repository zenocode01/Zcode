# Zcode 是什么?——给完全不懂编程的人看的说明

> 本文用生活化的语言解释 Zcode。如果你不是程序员,读这一篇就够了。
> 技术细节见 `README.md`;AI 代理使用指南见 `AGENTS.md`。

---

## 一、一句话说清楚

**Zcode 是一套"AI 员工手册库"**——它把教 AI 干活的方法写成一本本手册,让 AI 干活更有规矩、记住你的事、换工具也不失忆。

打个比方:

> 你家请了一位"超级管家"(AI)。这位管家能力很强,但有个毛病——你不给他写清楚"怎么干活",他就凭感觉来,经常干砸。
>
> Zcode 就是给这位管家准备的**一本本岗位手册 + 一本工作日志 + 一个记事本**:
> - **手册**告诉他每种活该怎么干(先问清楚需求再动手、写完要自己检查、出了问题怎么排查……)
> - **工作日志**记着他手头在干哪件事、干到哪一步了(像工地上的施工进度表)
> - **记事本**让他记住你的事(你喜欢的风格、上次踩过的坑)

---

## 二、它解决什么问题?

AI 助手(像 ChatGPT、Claude、Cursor 这些)单用的时候,有四个让人头疼的毛病:

| 毛病 | 表现 | Zcode 的解决办法 |
|---|---|---|
| **没规矩** | 你让它写个功能,它直接开写,结果方向全错 | 手册规定:先拷问需求 → 头脑风暴 → 写计划 → 批准了才能动手 |
| **忘事** | 上次说过的偏好、约定,下次全忘了 | 记事本(记忆层)让他长期记住;交接班记录让他每次都能续上 |
| **没法管进度** | 干到一半中断,下次不知道干到哪了 | 工作台(工单系统)像工地施工进度表,一眼看到哪张"工单"进行中 |
| **换工具就失忆** | 换个 AI 工具,能力全没了,要重新教 | 一套手册到处通用(适配 8 个主流 AI 工具),换工具只换"插座"不换"手册" |

## 三、它有什么功能?(大白话版)

### 1. 技能库:12 本"岗位手册"

每本手册教 AI 一种活该怎么干,可以随意组合:

| 手册 | 教 AI 干什么 | 什么时候用 |
|---|---|---|
| **拷问需求**(grill-me) | 把你的想法反复追问,挖出你没说的隐藏要求 | 你有个想法,还没想清楚 |
| **头脑风暴**(brainstorming) | 先出 2-3 个方案让你挑,批准前不写代码 | 要做一个新东西 |
| **写计划**(writing-plans) | 把方案拆成一步步可执行的小任务 | 方案定了,准备开工 |
| **测试先行**(tdd) | 先写"考试题"再写"答案",保证改不错 | 开发新功能、修 bug |
| **系统化修 bug**(diagnose) | 像侦探一样定位问题,不瞎改 | 东西坏了/变慢了 |
| **代码审查**(code-review) | 干完活让 AI 自己检查,问题分级处理 | 每次干完活 |
| **架构体检**(improve-arch) | 检查代码结构有没有变乱,提前治理 | 代码越来越难改时 |
| **会话接力**(handoff) | 交接班:把进度、决策、验证结果写下来 | 换人/换会话/换工具时 |
| **分工协作**(subagent-driven-development) | 派多个"小 AI"并行干活,主 AI 逐个验收 | 任务大且互不干扰时 |
| **自我进化**(evoskills) | AI 根据使用情况自己改进手册 | 手册反复用不好时 |
| **工单工作台**(workbench) | 项目管理看板:工单、阶段、进度、把关 | 项目里干活(见下) |
| **问路**(ask-zcode) | 不确定用哪个手册?问它 | 任何时候 |

### 2. 工单工作台:给项目立规矩

这是最"有纪律感"的功能,像工地管理:

- **工单**(tickets):每件事登记成一张工单(编号 T-001、T-002……)
- **阶段**:每张工单按固定流程走——`分析 → 计划 → 实现 → 验证 → 审查 → 提交`
- **关卡**:不能跳步。比如没写测试不许说"验证通过",没记录"怎么修好的"不许关单
- **进度表**(STATUS):一页纸看清所有工单状态,自动更新
- **验收制度**:关单前必须留下"根因/修复/验证"记录,且变更日志自动补录

**效果**:谁接手都能一眼看懂"现在干到哪了、下一步干什么",不会出现"干一半跑路没人知道干了啥"。

### 3. 记忆:AI 的记性

- **交接班记录**(handoff):每次会话结束时写下"这轮干了啥、下一步干嘛",下次打开就续上——不靠聊天记录
- **长期记忆**(mem0):AI 记住你的偏好、项目背景、踩过的坑,用"回忆"的方式检索,越用越懂你

### 4. 适配层:万能插座

- 一套手册**软链接**安装到 8 个主流 AI 工具(Claude、Cursor、Codex、Gemini、opencode 等)
- 换工具不用重新教,插上就能用

### 5. 自我进化:AI 帮 AI 改进

- 每次使用被记录,定期"体检"(审计):哪个手册总用不好 → 生成改进版 → 达标才发布
- 质量门槛:技能市场里的手册都要过校验(格式、命名、大小、无占位符)

## 四、框架是什么样?(四层结构,用盖房子类比)

```
┌─────────────────────────────────────┐
│ 第 3 层: 记忆与自我进化(档案室)       │  ← 记性好 + 会自我改进
├─────────────────────────────────────┤
│ 第 2 层: 工作流与工作台(施工指挥部)   │  ← 排计划、派工、验收、看板
├─────────────────────────────────────┤
│ 第 1 层: 技能库(员工手册库)           │  ← 12 本手册,教 AI 干活
├─────────────────────────────────────┤
│ 第 0 层: 适配层(万能插座)             │  ← 插哪个 AI 工具都能用
└─────────────────────────────────────┘
```

- **第 0 层(地基/插座)**:让所有 AI 工具都能读同一套手册——"翻译官 + 万能插座"
- **第 1 层(手册库)**:核心资产,12 本手册每本解决一个具体问题——"乐高积木,随意组合"
- **第 2 层(指挥部)**:把手册串成流水线,加项目看板、进度、验收——"施工进度表 + 验收制度"
- **第 3 层(档案室)**:记性(记事本)+ 自我改进(老师傅带徒弟,徒弟还反过来改手册)

## 五、我不会编程,怎么用?

**完全不用编程。** 分两种情况:

### 情况 A:我(普通人)直接用

你只需要一个装好的 AI 工具,然后把 Zcode 的"手册库"装进去(找人帮你跑一条安装命令,1 分钟)。之后:

1. 你正常跟 AI 对话,比如"帮我想个点子"——AI 会自动翻手册,按手册流程跟你互动(比如先问清楚需求)
2. 想让 AI 干活有进度、可交接?让 AI 帮你建一个"项目工作台",之后它会自己登记工单、推进阶段、报告进度
3. 换了个 AI 工具?把同一套手册插过去就行

### 情况 B:我(项目负责人)想看到进度

- 打开项目的 `STATUS.md`(一页纸进度表)或让 AI 执行"报告当前状态"
- 看 `CHANGELOG.md`(变更日志):每次改动自动记录,版本号自动递增
- 看 `tickets.md`(工单列表):所有待办、进行中、已完成一目了然

### 日常高频操作(对着 AI 说就行)

| 你想干什么 | 就告诉 AI |
|---|---|
| 想清楚一个想法 | "用头脑风暴帮我想想" |
| 修一个 bug | "用系统化调试帮我查" |
| 新项目开工 | "建个工作台,登记工单开始干" |
| 中途休息 | "记录交接记录" |
| 回来继续 | "读取交接记录,继续干活" |
| 看看进度 | "报告项目状态" |
| 换了工具 | 装一次手册,继续对话 |

## 七、小词典(遇到不懂的词看这里)

| 词 | 通俗解释 |
|---|---|
| 技能/手册 | 教 AI 干某类活的操作说明(SKILL.md) |
| 工单 | 一件待办事项,编号 T-XXX,有状态(待办/进行中/验收中/完成) |
| 阶段 | 工单的固定流程步骤(分析→计划→实现→验证→审查→提交) |
| 锚点 | 文档里用固定格式写的关键行(如 `Status: done`),机器能读懂 |
| 守卫/关卡 | 流程中不许跳步的强制检查(没测试不许验证通过) |
| 会话接力 | 交接班记录,让下次会话接着干 |
| 记忆 | AI 的长期记事本,按语义"回忆"检索 |
| 适配层 | 万能插座,让手册兼容不同 AI 工具 |
| 变更日志 | 每次改动的流水账,版本号自动递增 |
| pre-commit | 提交代码前的自动检查(相当于出厂质检) |
| 验证证据 | 测试跑出来的记录,证明"真的通过了" |
