# Zcode 使用手册——照着做就能用

> 本文是**手把手的操作指南**。你不需要会编程,只要会复制粘贴命令、会看输出提示。
> 概念讲解见 `docs/通俗说明.md`;开发者参考见 `README.md`。

---

## 0. 这份手册讲什么

你会学会:装好 Zcode → 建一个"项目工作台" → 让 AI 按规矩干活 → 用可视化界面管 git → 发布新版本 → 随时查看进度 → 换会话接着干。全程约 20 分钟。

**你需要准备**:
- 一台电脑(Windows / macOS / Linux 都行)
- 能联网
- 一个 AI 编程工具(opencode、Claude Code、Cursor 等,任选其一)
- 会打开"终端"(Windows 叫 PowerShell 或 CMD;macOS 叫"终端"App;Linux 就是那个黑窗口)

> 不认识终端?在电脑上搜索"终端"或"Terminal"就能找到。后面所有命令都是复制粘贴到终端里按回车。
> **Windows 用户注意**:下面示例用 `zcode` 命令,Windows 上装好后同样是 `zcode`(见第 1 步的 Windows 分支)。

## 1. 安装 Zcode(约 5 分钟)

打开终端,按顺序执行下面的命令。每条命令后面都解释了它是干嘛的。

### 第 1 步:给 Zcode 准备一个"独立工具箱"

```bash
cd Zcode-0.0                                    # 进入项目文件夹
python3 -m venv .venv                           # 建一个独立环境(不影响你电脑的其他软件)
```

> 如果提示找不到 `python3`:先装 Python(官网 python.org 下载安装,安装时勾选"Add to PATH")。
>
> **Windows 用户**:第 1、2 步的命令换成:
> ```powershell
> py -m venv .venv                                    # Windows 用 py 启动器建环境
> .venv\Scripts\pip install -e ./adapters             # 装进环境的命令不同
> ```

### 第 2 步:把 Zcode 装进工具箱

```bash
.venv/bin/pip install -e ./adapters
```

看到类似 `Successfully installed zcode` 就成功了。

### 第 3 步:把"技能手册"装到 AI 工具里(同时装好全局命令)

```bash
bash scripts/install.sh
```

**Windows 用户**(在 PowerShell 里):

```powershell
powershell -ExecutionPolicy Bypass -File ./scripts/install.ps1
```

这条命令一次做三件事:
1. 把 12 本"岗位手册"装到 `~/.agents/skills/`——你的 AI 工具能自动读到(Windows 用 Junction/复制,无需管理员)
2. 装好 `zcode` 全局命令(Windows: `~/.local/bin/zcode.cmd` 并自动加入用户 PATH)——**之后任何目录直接敲 `zcode` 就行**
3. 检查 zcode 包是否可用,不可用会提示安装命令

### 第 4 步:验证装好了

```bash
zcode skills list
```

看到一列技能名字(ask-zcode、brainstorming、tdd、workbench……)就说明装好了。

> 提示:如果提示找不到 zcode,先 `python3 -m pip install -e ./adapters` 把包装进系统 Python,再重跑一次 install.sh。

## 2. 建一个项目工作台(约 3 分钟)

工作台 = 项目的"施工进度表 + 验收制度"。建好后,所有活都登记成"工单",一步步推进。

### 新建项目(约 1 分钟)

```bash
zcode ticket init my-first-project              # 创建项目并初始化工作台
cd my-first-project
```

看到 `✓ 工单工作台已就绪` 就成功了。它自动帮你:建文件夹、初始化 git、装好"提交前检查",**并提问两行配置**——项目简介(Domain)和验证命令(TestCommand),回答后直接写入,不用手动编辑文件。

> 已有项目(比如你自己写的代码文件夹)想中途嵌入?在项目文件夹里执行 `zcode ticket init --existing .`——它只补缺失文件、不碰你已有的内容,**自动把"工单工作台协议"追加到 AGENTS.md(原内容保留)**,同样会提问配置。一分钟完成嵌入。

## 3. 日常干活:完整走一遍(约 10 分钟)

我们演示一个完整流程:登记任务 → 开工 → 一步步推进 → 完工。复制粘贴即可。

### 3.1 登记一张工单

```bash
zcode ticket add "做一个登录功能"
```

看到 `✓ 已新增 T-001:做一个登录功能`。工单自动编号 T-001、T-002……

### 3.2 开工(拾取工单)

```bash
zcode ticket begin T-001
```

它会:把工单标记为"进行中"、自动创建分支(不影响主代码)、告诉你去填 Domain。

### 3.3 推进阶段

干活按固定流程:`分析 → 计划 → 实现 → 验证 → 审查 → 提交`。每完成一步,推进一下:

```bash
zcode ticket phase plan          # 分析完,进计划
zcode ticket phase implement     # 计划完,开始实现
zcode ticket phase verify        # 实现完,验证(测试)
```

> 卡住了?没关系,这是"关卡"在起作用——比如没写测试就不让进"验证"。提示会告诉你缺什么。

### 3.4 验证通过/失败

- 测试通过:`zcode ticket phase verify --green`(标记绿,进入审查)
- 测试失败:`zcode ticket phase verify --red`(回到实现继续改)

### 3.5 完工:记录 + 审查 + 提交

```bash
zcode ticket transition T-001 review   # 工单进入"审查中"
zcode ticket resolve T-001 "根因: 缺登录逻辑; 修复: 加了账号密码校验; 验证: 测试通过"   # 记录怎么修的
zcode ticket phase review --green      # 审查通过
zcode ticket phase commit --pass       # 准备提交
git add -A && git commit -m "T-001 登录功能"   # 正式提交(提交前会自动检查)
```

> 提交时如果被拦,读一读提示——通常是"阶段没到"或"工单还在进行中",按提示执行对应命令即可。

### 3.6 关单(完工收尾,全自动)

```bash
zcode ticket close T-001
```

关单时 Zcode 自动帮你:记录到变更日志(CHANGELOG)、提交状态文件、合并分支、复位状态。看到 `✓ 状态文件已自动提交,工作区干净` 就彻底完工了。

## 4. 不想敲命令?用 AI 对话驱动

装了技能后,AI 工具会自动读手册。你只需要**说人话**:

| 你想干什么 | 对 AI 说 |
|---|---|
| 想清楚想法 | "用头脑风暴帮我把这个想法理清楚" |
| 登记任务 | "帮我建一张工单:做一个登录功能" |
| 开始干 | "拾取 T-001 开始干" |
| 看进度 | "报告项目状态" / "下一步干什么" |
| 干一半休息 | "保存交接记录" |
| 回来继续 | "读取交接记录继续" |
| 修 bug | "用系统化调试帮我查这个问题" |

AI 会自己调用 `zcode` 命令,你只需要确认它做得对不对。

## 5. 随时查看进度

```bash
zcode ticket context      # 一屏摘要:现在干到哪、当前工单、最近流转(接手先看这个)
zcode ticket status       # 刷新 STATUS.md(一页纸总览)
zcode ticket next         # 建议下一步:哪些工单可以开工
zcode ticket log          # 流转历史(倒序)
zcode ticket validate     # 全量体检:状态有没有矛盾(提交前跑一下)
```

打开项目里的 `STATUS.md` 文件,一页纸看完全部工单状态——不用问任何人。

## 6. 跨会话接力(换人/换工具都能续上)

### 干到一半要停

```bash
zcode handoff save --goal "登录功能" --next "下一步: 写测试"
```

### 下次回来

```bash
zcode handoff load
```

> 在"工单项目"里保存交接记录时,"进行中"会自动带上当前工单(T-XXX 和阶段)——不用手填,也不会和进度表打架。

### 想让它长期记住你的偏好

```bash
zcode memory add "我喜欢简洁的代码注释"          # 记一条
zcode memory search "注释风格"                    # 问它记没记住
```

## 7. 用 zcode 管理代码仓库(不用记 git 命令)

写代码最怕两件事:改坏了想回退、多人协作乱了套。git 就是解决这个的"存档机",但它的命令又长又难记。Zcode 把 git 包装成**看得见的界面**。

### 7.1 全屏界面(最直观)

在项目文件夹里敲:

```bash
zcode git
```

会出现一个全屏界面,键盘上下左右操作:

- 左边 8 个面板:状态 / 差异 / 提交 / 日志 / 分支 / 储藏 / 远端 / 进阶
- 右边是文件列表,底部是状态栏(当前分支、改了哪些、有没有冲突)
- `空格` = 勾选文件(暂存)、`回车` = 看改了什么、`c` = 提交、`q` = 退出、`?` = 帮助

日常三步:

1. 改完代码 → `zcode git` → `空格` 勾选文件 → `c` 输入提交说明 → 回车
2. 想看历史 → 按 `Tab` 切到"日志"面板 → `回车` 看某次提交详情
3. 合并冲突了 → 状态栏显示"冲突:N" → 选中冲突文件 → `o` 保留本地 / `t` 保留对方

### 7.2 逐条命令(服务器/脚本里也能用)

不能显示全屏界面时(服务器、自动化脚本),用逐条命令,输出同样带颜色:

```bash
zcode git status              # 看改了哪些文件(彩色分组)
zcode git log                 # 看提交历史
zcode git diff                # 看具体改了什么
zcode git add 文件            # 勾选文件(支持多个)
zcode git commit -m "说明"    # 提交
zcode git push / pull         # 推上去 / 拉下来
zcode git checkout 分支名     # 切换分支
```

> 危险操作(比如 `reset --hard`、强制推送)执行前会先警告,不会无声执行。

## 8. 发布新版本(给成果打个"正式标签")

项目做了一阵子,想标记"这一版就是正式版",一个命令搞定:

```bash
zcode release patch      # 小修小补(0.4.0 → 0.4.1)
zcode release minor      # 加了新功能(0.4.0 → 0.5.0)
zcode release major      # 大改版(0.4.0 → 1.0.0)
zcode release 0.5.0      # 或直接指定版本号
```

它自动帮你:把版本号统一改到 5 个文件、把"未发布"的变更记录整理成正式版本、打一个 git 标签(`v0.4.0` 这种)。

想先看看它会做什么(不真的执行):

```bash
zcode release minor --dry-run
```

想顺便推到远程仓库(比如 GitHub):

```bash
zcode release minor --push
```

> 版本号规则(语义化版本):三位数 `主版本.次版本.补丁`。改 bug 加补丁(patch)、加功能加次版本(minor)、大改版加主版本(major)。

## 9. 给 pi-agent 装 Zcode(可选)

如果你用的是 **pi-agent** 这个 AI 工具,Zcode 给它做了"深度插件":能在 pi 里直接敲 `/zcode` 命令、让 AI 自动调 Zcode 的能力。

```bash
pi install git:github.com/zenocode01/Zcode.git    # 一键装齐技能 + 插件
```

装好后:

- 输入 `/zcode skills list` —— 在 pi 里直接看技能清单
- 输入 `/zcode ticket context` —— 看当前工单状态
- AI 会自动调用 `zcode_*` 工具(查工单、搜记忆、查技能、查术语表),不用你手动敲

> 前置:先按第 1 步装好 `zcode` 命令(插件要靠它)。插件只提供"只读"能力给 AI,写操作(改工单、提交代码)仍需你手动发命令,安全可控。

卸载:`pi remove git:github.com/zenocode01/Zcode.git`

## 10. 常见问题(FAQ)

| 问题 | 怎么办 |
|---|---|
| `zcode: command not found` | 命令没装好。回到第 1 步重装;或用完整路径 `.venv/bin/zcode` |
| `当前目录不是工单项目` | 说明这个文件夹没建工作台。用 `zcode ticket init .`(空文件夹)或 `init --existing .`(已有项目) |
| 提交被拦:`Phase 是 analyze` | 按流程推进:先 `begin` 工单,再一步步 `phase` 到 review/commit |
| 提交被拦:`STATUS.md 已过期` | 跑一下 `zcode ticket status` 刷新 |
| 提交被拦:测试失败(测试门禁) | 修好测试再提交;临时绕过:`git config zcode.test-gate false` |
| close 被拒:缺修复记录 | 先 `zcode ticket resolve T-XXX "根因+修复+验证"` |
| 分支自动合并冲突 | 提示会中止并告知;手动解决冲突后重试 close |
| 想关掉自动分支 | 改 `docs/CONTEXT.md` 的 `BranchMode: auto` 为 `manual` |
| 不想要工作台了 | 删掉 `tickets.md`、`STATUS.md`、`.vibe/` 即可(不影响代码) |
| `zcode git` 说"不在 git 仓库内" | 这个文件夹没 git。先 `zcode ticket init` 建工作台(会自动 git init),或进到已有 git 项目里 |
| `zcode release` 说"工作区有未提交改动" | 先 `git add -A && git commit` 提交当前改动,再 release |

## 11. 常用命令速查表

```
zcode ticket init <项目名>            # 建工作台(已有项目加 --existing)
zcode ticket add "标题"               # 登记工单
zcode ticket begin T-001              # 开工
zcode ticket phase <阶段>             # 推进: plan/implement/verify/review/commit
zcode ticket transition T-001 review  # 工单进审查
zcode ticket resolve T-001 "记录"     # 记录修复情况
zcode ticket close T-001              # 关单(自动收尾)
zcode ticket context                  # 接手先看:一屏摘要
zcode ticket next                     # 建议下一步
zcode ticket validate                 # 全量体检
zcode handoff save/load               # 交接班记录
zcode memory add/search               # 长期记忆
zcode git                              # 可视化 git(全屏界面)
zcode git status/log/add/commit        # 逐条 git 命令
zcode release patch/minor/major        # 发布新版本(--dry-run 预览)
```
