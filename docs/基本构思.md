## 一、核心理念：从"技能集合"到"技能操作系统"

你的目标本质上是构建一个 **AI 技能的"操作系统"** ——它不是另一个重型框架，而是一个轻量的、可插拔的"技能运行时环境"。

借鉴两个项目的核心设计哲学：
- **Matt Pocock 的"小、可组合、随时可改"** ：每个技能是独立的 Markdown 指令集，像乐高积木
- **Superpowers 的"强制工作流"** ：通过启动时注入引导上下文，让 Agent 先查技能再行动

你的统一工作流集应定位为：**一个轻量级的技能编排与记忆层**，而非另一个"包办一切"的框架。

> **实现状态（2025-08）**：四层架构已全部有真机落地（详见各层"已实现"标注与 `docs/开发偏好与默认配置.md`）。

### Layer 0：跨平台适配层 —— 实现"即插即用"

这是实现"在任何 CLI、桌面端、Agent 软件中即插即用"的关键。

**核心机制**：
1. **统一技能格式**：以 Anthropic 的 Agent Skills 开放标准为基础，所有技能用 `SKILL.md` 封装（双版本：`SKILL.md` 云 / `SKILL.local.md` 本地小模型）
2. **工具映射表**：将不同平台的工具调用映射到统一接口（`adapters/zcode/tool_mapping.py`，CLI 查看 `zcode tools list`）
   - 统一接口 `spawn / parallel / todo / review` → Claude 的 `Task` / Codex 的 `spawn_agent` / Kimi Code 的 `Agent` / opencode 的 `run` 等
   - 无原生子代理的平台（Cursor / Gemini / Pi / Reasonix）标注降级路径
3. **软链接桥接**：`scripts/install.sh` 将技能软链到各平台技能目录
   - 主目标 `~/.agents/skills`（跨工具事实标准：opencode / Kimi Code / Pi / Cursor / Reasonix 原生支持）
   - 平台原生目录双保险：`~/.claude/skills`、`~/.cursor/skills`、`~/.codex/skills`、`~/.gemini/skills`、`~/.config/opencode/skills`、`~/.kimi-code/skills`、`~/.pi/agent/skills`、`~/.reasonix/skills`
4. **本地模型适配**：profile 能力声明 + OpenAI 兼容 Provider（llama.cpp）+ 工具调用三层降级（详见第五节）

**已实现**：`install.sh`（8 平台）、8 份 `INSTALL.md`、`zcode platforms list`、工具映射表。

### Layer 1：核心技能库 —— 实现"可复用"

整合两个项目的精华技能，按"失败模式"组织（已移植 9 个，均含标准版 + 本地精简版）：

| 类别 | 技能 | 说明 | 来源 |
|------|------|------|------|
| 需求对齐 | `grill-me` | 设计树逐轮拷问，挖沉默假设（仅用户调用） | Matt Pocock |
| 需求对齐 | `brainstorming` | 创造性工作前必用，硬门：批准前禁写代码 | Superpowers |
| 规划 | `writing-plans` | bite-sized 计划，No Placeholders 硬规则 | Superpowers |
| 测试驱动 | `tdd` | 红绿重构 | Matt Pocock |
| 调试 | `diagnose` | 紧致反馈回路 + 排序假设 + 回归测试 | Matt Pocock |
| 代码审查 | `code-review` | SHA 派审 + 分级反馈 | Superpowers |
| 架构治理 | `improve-arch` | 浅模块→深模块（仅用户调用） | Matt Pocock |
| 会话接力 | `handoff` | 会话间快照接力（目标/决策/验证） | 自研（模板化 CLI） |
| 子代理 | `subagent-driven-development` | 独立上下文/ledger/逐任务审查/5轮修复cap | Superpowers |

**关键设计原则**（来自 Matt Pocock）：
- 每个技能解决一个具体的"翻车场景"
- 技能之间松散独立，可随意组合
- Agent 在合适语境自动加载（model-invoked）；`grill-me` / `improve-arch` 为 `disable-model-invocation`（仅用户调用）

### Layer 2：技能编排与工作流层 —— 实现"可扩展"

**核心机制**（均已实现）：

1. **确定性工作流模板**（`workflows/`，本地小模型默认）：显式线性步骤 + 条件分支，外部 runner 驱动，模型只做每步决策。步骤类型：`skill` / `prompt` / `command` / `subagent`。示例：`feature-dev`（grill-me → brainstorming → writing-plans → tdd → code-review）
2. **MetaSkill 自由编排**（`metaskills/`，强模型可选增强）：把"可用技能 + 编排规则"交给模型生成计划，再复用确定性执行器。profile 字段 `orchestration`：本地默认 `deterministic`，强模型可配 `meta`
3. **子代理编排**（`skills/subagent-driven-development`）：每任务派全新子代理（独立上下文、文件传 brief），ledger 恢复地图，逐任务审查（规格 + 质量双判定），5 轮修复 cap + breaker 裁决，最终全分支审查；配套 3 个提示词模板

**已实现**：`zcode workflow list/run`、`zcode metaskill list/run`、工具映射表。

### Layer 3：自我迭代与记忆层 —— 实现"自我迭代升级"和"记忆"

这是整个架构最具创新性的部分。

#### 3.1 技能级记忆（Skill-level Memory）—— 已实现

**问题**：当前 AI 会话是"失忆"的，每次都要重新解释。

**解决方案（已落地）**：
- **mem0 本地三件套**（`zcode memory add/search/list`）：LLM（Qwen3.6-35B）+ Embedding（Qwen3-Embedding-8B，自定义 HttpEmbedder 对接 llama.cpp `/embedding` 端点）+ Qdrant 本地向量库（`~/.zcode/memory`）；检索零 LLM，混合检索（语义 + BM25 词形还原 + 实体加权，spaCy 已启用）
- **统一记忆接口 MemStore**（`zcode/memory.py`）：`add/search/list/update/delete`，内部 mem0 实现，为自建替换留抽象边界（先 mem0 后自建路线）
- **记忆写入四级降级**（本地小模型）：L0 纯 embedding（`infer=False`）→ L1 简化提取提示词（默认）→ L2 容错解析 → L3 批量合并
- **技能级记忆文件夹**（`.memory/`，不入库）：`experience.log`（使用经验）、`improvements.md`（改进建议）、`context-snapshot.json`（项目快照）

#### 3.2 会话接力（agent-handoff）—— 已实现

- `zcode handoff save/load`：模板化快照（目标/已完成/进行中/决策/验证/下一步），存项目 `.memory/handoff.md` 或全局 `~/.zcode/handoff.md`
- `skills/handoff`：会话开始 load 恢复、结束 save 接力，不依赖历史聊天记录

#### 3.3 自我迭代（Self-Evolution）—— 未实现（Phase 4 规划）

**核心机制**：元技能（Meta-Skill）持续监控和优化其他技能。

借鉴以下项目：
- **EvoSkills**：始终运行的元技能，自动将重复工作流捕获为新技能，通过"生成器-验证器"循环迭代进化
- **task-observer**：观察工作会话，捕获修正和判断，自动转化为技能改进
- **MUSE-AutoSkill**：按需生成新技能、存储复用、通过单元测试和运行时反馈评估优化

**工作流程**：
```
1. 监控 → 2. 捕获 → 3. 评估 → 4. 迭代 → 5. 验证 → 6. 发布
```

## 五、本地小模型优化（定稿）

面向本地部署的小模型（Qwen3.6-35B，llama.cpp，256K 上下文）的专项优化设计。三条原则：

1. **LLM 只用在必须的地方**：提取/总结类任务才调用模型；检索、去重、排序走确定性代码
2. **把"智能"前置到规则里**：能用模板、检索、规则树表达的，不指望模型自由发挥
3. **同一套技能格式，双版本内容**：标准版（云）+ 精简版（本地），profile 机制切换

### 5.1 小模型能力画像

| 能力维度 | 云前沿模型 | 本地 14B-35B 模型 | 优化影响 |
|----------|-----------|-----------------|---------|
| 上下文窗口 | 100K-200K+ | 8K-256K（实际 256K） | 技能按需加载，不全量注入 |
| 指令遵循 | 强 | 中等，复杂指令易走样 | 技能短句、单职责、步骤少 |
| JSON/结构化输出 | 稳定 | 不稳定 | 极简输出格式 + 容错兜底 |
| 工具调用 | 原生稳定 | 弱（Qwen3 系原生可用） | 三层降级策略 |
| Token 成本 | 贵 | 便宜但慢 | 检索零 LLM，写入低频 |

### 5.2 记忆层本地化

- **本地三件套**：LLM（llama.cpp 端点）+ Embedding（llama.cpp `/embedding` 端点）+ Qdrant 嵌入式向量库
- **写入四级降级**（add 的 LLM 提取是唯一热点）：L0 `infer=False` 纯 embedding → L1 简化提取提示词（默认）→ L2 容错解析 → L3 批量合并
- **检索零 LLM**：mem0 search 无 query rewrite，纯 embedding + BM25 + 实体加权
- **写入频率**：低频批量回写（会话结束/里程碑/显式触发），省本地算力
- **技能记忆回写模板化**：固定模板由代码填充，不消耗模型 token

### 5.3 技能内容精简

| 维度 | 标准版（云） | 精简版（本地） |
|------|-------------|---------------|
| 文件体积 | ≤ 8K tokens | ≤ 3K tokens（256K 上下文下为建议值） |
| 步骤数 | 可 8-10 步 | ≤ 5-7 步，线性 |
| 句式 | 可含背景解释 | 短句、动词开头、单职责 |
| 条件分支 | 可嵌套 | 显式扁平化 |
| 输出 | 复杂结构 | 一行一字段，避免嵌套 JSON |
| 兜底 | 隐含判断力 | 显式兜底动作 |

- 双版本：`SKILL.md` / `SKILL.local.md`，由 profile 的 `skill_variant` 决定加载哪个
- 结构化输出：必须 JSON 的场景给"填空式"模板；其余用极简列表格式

### 5.4 推理框架适配

- **统一基准**：OpenAI 兼容协议（llama.cpp `llama-server` `/v1`）
- **工具调用三层降级**（`zcode/providers/tool_fallback.py`）：
  - **L2 原生 tool calling**：模型声明支持 tools（Qwen3 系实测可用）→ 直接透传
  - **L1 提示词编码**：输出 `<tool>名</tool><args>JSON</args>`，解析器提取（含非法 JSON 容错）
  - **L0 无工具模式**：模型只输出决策标签，外部 runner 执行
  - 探测：`detect_tool_level()` 先测 L2 再降级 L1
- **Profile 机制**（`adapters/profiles/local-qwen3.6-35b.yaml`）：能力声明（model_family / context_window / tool_level / json_reliability / skill_variant / orchestration / memory.*），驱动技能版本与记忆策略
- **推理模型适配**：默认 `max_tokens=4096`（思考占预算）、content 空时降级返回 `reasoning_content`
- **上下文管理**：启动只注入技能索引，激活技能时才读完整 `SKILL.md`

### 5.5 落地验证（真机）

- 工具调用：`tool_level=2`（原生 tool calling）✅
- MetaSkill 编排：真实模型自主生成计划（跳过 grill-me、遵守硬门）✅

## 六、总结：一个统一的"技能操作系统"

这个架构的本质是 **将 AI 技能从"一次性指令"升级为"可安装、可组合、可记忆、可进化"的能力产品**。

它不是一个 monolithic 的框架，而是一套**轻量的规范和工具链**：
- **规范**：统一的技能格式（双版本）+ 工具映射表 + 记忆协议 + profile 能力声明
- **工具链**：一键安装脚本 + 跨平台适配器 + 工作流/元技能引擎 + 子代理编排 + 记忆层 + 会话接力

最终效果是：**你只需维护一个技能仓库，就能在任何 AI 工具中获得一致的工作流能力，且这些能力会随着使用而不断进化和记忆**。
