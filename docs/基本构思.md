## 一、核心理念：从“技能集合”到“技能操作系统”

你的目标本质上是构建一个 **AI 技能的“操作系统”** ——它不是另一个重型框架，而是一个轻量的、可插拔的“技能运行时环境”。

借鉴两个项目的核心设计哲学：
- **Matt Pocock 的“小、可组合、随时可改”** ：每个技能是独立的 Markdown 指令集，像乐高积木
- **Superpowers 的“强制工作流”** ：通过启动时注入引导上下文，让 Agent 先查技能再行动

你的统一工作流集应定位为：**一个轻量级的技能编排与记忆层**，而非另一个“包办一切”的框架。

## 二、核心架构：三层设计

```
┌─────────────────────────────────────────────────────────────┐
│                    统一工作流集 (Meta-Framework)              │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: 自我迭代与记忆层（Meta-Skills + 记忆系统）          │
│  - 技能自我进化（EvoSkills / task-observer）                 │
│  - 技能级记忆（Acontext / skill-evo）                       │
│  - 会话接力与项目记忆（agent-handoff-skill）                │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: 技能编排与工作流层（Workflow Engine）              │
│  - 工作流模板（MetaSkill）                                  │
│  - 子代理编排（subagent-driven-development）                │
│  - 跨技能依赖与触发规则                                     │
├─────────────────────────────────────────────────────────────┤
│  Layer 1: 核心技能库（Core Skills）                         │
│  - Matt Pocock 风格：grill-me, tdd, diagnose, improve-arch  │
│  - Superpowers 风格：brainstorming, writing-plans, code-review│
│  - 自定义扩展技能                                           │
├─────────────────────────────────────────────────────────────┤
│  Layer 0: 跨平台适配层（Adapter Layer）                     │
│  - 工具映射（tool mapping）                    │
│  - 插件格式转换（Claude/Cursor/Codex/Gemini...）│
│  - 软链接桥接（ai-skill-link）                  │
└─────────────────────────────────────────────────────────────┘
```

### Layer 0：跨平台适配层 —— 实现“即插即用”

这是实现“在任何 CLI、桌面端、Agent 软件中即插即用”的关键。

**核心机制**：
1. **统一技能格式**：以 Anthropic 的 Agent Skills 开放标准为基础，所有技能用 `SKILL.md` 封装
2. **工具映射表**：参考 Superpowers 的做法，将不同平台的工具调用映射到统一接口
   - Claude 的 `Task` → Codex 的 `spawn_agent`
   - Claude 的 `TodoWrite` → Codex 的 `update_plan`
3. **软链接桥接**：通过 `ai-skill-link` 或 `Skiller`将技能仓库软链接到各平台的技能目录
   ```bash
   # 一次安装，到处可用
   npx skills@latest add your-workflow-suite
   # 自动桥接到 Claude Code、Cursor、Codex、Gemini CLI 等
   ```

**交付物**：一个 `install.sh` 脚本 + 各平台的 `plugin.json` / `INSTALL.md` 适配文件

---

### Layer 1：核心技能库 —— 实现“可复用”

整合两个项目的精华技能，按“失败模式”组织：

| 类别 | Matt Pocock 技能 | Superpowers 技能 | 说明 |
|------|------------------|------------------|------|
| 需求对齐 | `/grill-me`, `/grill-with-docs` | `brainstorming` | 先拷问再编码 |
| 规划 | - | `writing-plans` | 写实现计划 |
| 测试驱动 | `/tdd` | `test-driven-development` | 红绿重构 |
| 调试 | `/diagnose` | `systematic-debugging` | 系统化诊断 |
| 代码审查 | - | `requesting-code-review` | 强制审查 |
| 架构治理 | `/improve-codebase-architecture` | - | 防止代码熵增 |
| 子代理 | - | `subagent-driven-development` | 并行分工 |

**关键设计原则**（来自 Matt Pocock）：
- 每个技能解决一个具体的“翻车场景”
- 技能之间松散独立，可随意组合
- Agent 在合适语境自动加载（model-invoked）

---

### Layer 2：技能编排与工作流层 —— 实现“可扩展”

**核心机制**：

1. **MetaSkill（元技能）** ：不写固定流程，而是把规则和可用技能告诉模型，让它自己编排流程
   ```markdown
   # MetaSkill: 功能开发工作流
   当用户说"开发一个新功能"时：
   1. 自动触发 brainstorming → 产出设计文档
   2. 自动触发 writing-plans → 产出任务列表
   3. 对每个任务：subagent-driven-development + tdd
   4. 全部完成后：requesting-code-review
   ```

2. **工作流模板**：将多个子技能的执行流程打包成可复用的“工作流模板”
   - 下次遇到同类任务，只需说“用功能开发模板”
   - 支持参数传递、错误兜底

3. **子代理编排**：参考 Superpowers 的 `subagent-driven-development`，让多个 Agent 并行/分工执行任务，主 Agent 负责审查和协调

### Layer 3：自我迭代与记忆层 —— 实现“自我迭代升级”和“记忆”

这是整个架构最具创新性的部分，整合了多个前沿项目的能力。

#### 3.1 技能级记忆（Skill-level Memory）

**问题**：当前 AI 会话是“失忆”的，每次都要重新解释。

**解决方案**：借鉴以下项目：
- **Acontext**：自动从 Agent 运行中捕获学习成果，存储为技能文件
- **skill-evo**：用某个技能时发现的 bug、踩的坑、更好的做法，结构化记录下来，下次写回 `SKILL.md`
- **agent-handoff-skill**：在会话之间建立连续性记忆，让未来的 Agent 能恢复目标、状态、决策、验证结果，不依赖历史聊天记录

**实现方式**：
```
每个技能目录下维护一个 `.memory/` 文件夹：
- experience.log: 每次使用的经验记录
- improvements.md: 累积的改进建议
- context-snapshot.json: 项目上下文快照
```

#### 3.2 自我迭代（Self-Evolution）

**核心机制**：元技能（Meta-Skill）持续监控和优化其他技能。

借鉴以下项目：
- **EvoSkills**：作为始终运行的元技能，监督其他技能，自动将重复工作流捕获为新技能，通过“生成器-验证器”循环迭代进化
- **task-observer**：观察工作会话，捕获修正和判断，自动转化为技能改进
- **MUSE-AutoSkill**：按需生成新技能、存储复用、通过单元测试和运行时反馈评估优化

**工作流程**：
```
1. 监控 → 2. 捕获 → 3. 评估 → 4. 迭代 → 5. 验证 → 6. 发布
```
- **监控**：记录每次技能使用的上下文、输入、输出、用户修正
- **捕获**：识别重复模式，提炼为新技能或改进现有技能
- **评估**：通过单元测试和运行时反馈评分
- **迭代**：生成改进版本，用验证器测试
- **验证**：只有评分达阈值才发布
- **发布**：更新技能文件，同步到各平台

## 四、关键技术选型建议

| 组件 | 推荐方案 | 理由 |
|------|----------|------|
| 技能格式 | Anthropic Agent Skills 标准 | 最广泛兼容 |
| 跨平台桥接 | `ai-skill-link`+ `Skiller` | 软链接方式最轻量 |
| 技能管理 | `npx skills` | 已形成生态 |
| 记忆层 | Acontext或自建 | 开源可定制 |
| 自我迭代 | EvoSkills+ task-observer | 验证器驱动，质量可控 |
| 插件市场 | Claude 官方市场+ 自建市场 | 官方+自建双通道 |

## 五、总结：一个统一的“技能操作系统”

这个架构的本质是 **将 AI 技能从“一次性指令”升级为“可安装、可组合、可记忆、可进化”的能力产品**。

它不是一个 monolithic 的框架，而是一套**轻量的规范和工具链**：
- **规范**：统一的技能格式 + 工具映射表 + 记忆协议
- **工具链**：一键安装脚本 + 跨平台适配器 + 元技能引擎 + 自我迭代循环

最终效果是：**你只需维护一个技能仓库，就能在任何 AI 工具中获得一致的工作流能力，且这些能力会随着使用而不断进化和记忆**。
