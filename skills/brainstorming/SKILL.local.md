# brainstorming（本地精简版）

## 何时使用

- 任何新功能/新组件/行为修改的创造性工作之前

## 工作流程

1. 读项目上下文（关键文件）
2. 澄清问题：一次一个，问目的/约束/成功标准
3. 给 2-3 个方案 + 权衡 + 推荐
4. 分节呈现设计，逐节问"可以吗"
5. 获批准后写设计文档到 docs/specs/ 并提交
6. 下一步才写实现计划（writing-plans）

## 输出格式

- 方案: <A/B/C + 推荐>
- 文档: docs/specs/<日期>-<主题>-design.md

## 兜底

- 用户催着写代码 → 提示"需先批准设计"，给最短设计快速过
- 用户说"太简单不用设计" → 仍给 2-3 句设计让其确认
