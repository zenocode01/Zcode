# evoskills — 技能自我迭代（标准版）

## 何时使用

- 定期执行（推荐：每会话结束时顺手跑一次 `audit`）
- 技能使用中出现反复失败、用户多次纠正同一问题
- 用户明确要求"自我迭代/改进技能"

## 工作流程（监控 → 捕获 → 评估 → 迭代 → 验证 → 发布）

1. **捕获**：每次技能使用后（或会话结束时），记录使用情况：
   ```
   zcode skill log <技能名> 成功|失败|改进 --context "<场景>" --lesson "<一句话教训>"
   ```
   教训必须具体可操作（"用户需求含隐藏假设"比"没做好"有用）。
2. **评估**：运行审计，查看健康度：
   ```
   zcode skill audit <技能名>
   ```
   关注：成功率、失败/改进的教训、未处理改进建议。
3. **判定**：`needs_revision` 为真（成功率 < 70% 或未处理改进建议 ≥ 2 条）→ 进入迭代；否则继续监控。
4. **迭代**：生成改进版本——读取 `.memory/experience.log` 的教训与 `.memory/improvements.md` 的建议，逐条评估是否修改 `SKILL.local.md`（本地版优先）：
   - 教训指向同一环节反复失败 → 该环节补"显式兜底动作"
   - 建议明确且不违反设计哲学 → 采纳
   - 保持技能"小、可组合"：不因一次个案膨胀体积
5. **验证**：用改进后的技能重跑一次近期失败过的同类任务，确认改进生效且无回归；记录验证结果到 `.memory/experience.log`（结果填"改进"或"成功"）。
6. **发布**：确认有效后：
   - 在 `.memory/improvements.md` 把已采纳建议勾选为 `- [x]`
   - 技能文件更新即生效（`~/.agents/skills` 为软链，指向仓库）
   - 如改动影响面大，同步更新 `SKILL.md`（标准版）

## 硬规则

- **质量优先**：只有验证通过的改进才发布；评分达阈值才迭代（`SUCCESS_RATE_THRESHOLD=0.7`、`IMPROVEMENTS_THRESHOLD=2`）
- **不因个案膨胀**：一次教训不足以改技能；同类失败 ≥ 2 次或建议明确才采纳
- **双版本同步**：本地版改动验证有效后，标准版如有对应内容需同步，避免两版漂移
- 发布后立即重新 audit 确认健康度回升

## 输出格式

- 记录：`.memory/experience.log`（追加）
- 评估：`zcode skill audit` 报告（使用数/成功率/教训/改进建议/健康度）
- 发布：更新的 `SKILL.local.md` / `SKILL.md` + 勾选的 `improvements.md`

## 兜底

- 无使用记录 → 报告"样本不足"，不强制迭代
- 改进版本验证失败 → 回滚（git checkout 或人工还原），记录教训
- 本地小模型 → 用精简版（3 轮收敛，改动更保守）
