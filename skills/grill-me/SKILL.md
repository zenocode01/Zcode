# grill-me — 需求拷问（标准版）

> 移植自 Matt Pocock 技能集。仅用户主动调用（`disable-model-invocation`），模型不得自动触发。

## 何时使用

- 用户想压力测试某个计划、决定或想法
- 用户使用 "grill me" / "拷问我" 等触发短语

## 工作流程

1. **构建设计树**：把讨论映射为设计树——每个决定分支成其下游决定，标出依赖关系。
2. **按轮次工作**：当前"前沿" = 所有前置条件已确定的决定；只在前沿上提问。
3. **每轮问整个前沿**：给每个问题编号，格式固定：
   - `❓ Q# - 标题: 正文`
   - `➡️ 推荐答案: <你的建议>`
   等用户回答完所有问题，才进入下一轮。
4. **重塑树**：用户回答后更新设计树 → 重算前沿 → 迭代。
5. **职责划分（硬规则）**：
   - 找事实是 Agent 的职责——需要环境事实（文件系统/工具/代码库）时派子代理查证，绝不让用户做你能查到的事
   - 做决定是用户的职责——每个决定必须逐个提问并等待回答
6. **结束条件**：前沿为空（每个分支都访问过、无沉默假设），且用户确认达成共识后，才允许行动。

## 输出格式

- 设计树：<决定 → 下游决定> 的依赖图
- 每轮问题：❓ Q# + ➡️ 推荐答案
- 最终交付：与用户达成的"共享理解"（完整遍历的设计树）

## 兜底

- 子代理探索结果未返回 → 不阻塞本轮其余问题，下轮并入
- 问题依赖未回答的前置问题 → 留到下一轮，不提前问
- 不确定用户的答案 → 不猜测，等待用户明确回答
