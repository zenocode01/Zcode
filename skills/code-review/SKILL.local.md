# code-review（本地精简版）

## 何时使用

- 每个任务完成、合并 main 之前

## 工作流程

1. git diff 看改动范围
2. 逐项自查：
   - 每个改动有对应需求/测试吗
   - 边界条件处理了吗（空值/越界/并发）
   - 错误处理了吗（失败路径）
   - 有重复代码或死代码吗
   - 命名与既有代码一致吗
3. 问题分级：Critical 立即修 / Important 修完再继续 / Minor 记下
4. 修复后重新跑测试确认全绿

## 输出格式

- 问题: <级别> <位置> <描述>
- 结论: 通过 / 需修复

## 兜底

- 无法自查（改动过大） → 拆小 diff 分块审查
- 本地模型不确定 → 把可疑点列给用户确认
