# improve-arch（本地精简版）

## 何时使用

- 用户要求扫描/改善代码库架构时

## 工作流程

1. git log 找热点文件
2. 读热点模块，找"浅模块"（薄壳没内容、复杂度漏到调用处）
3. 对疑似浅模块做删除测试：删掉它是集中复杂度还是搬走
4. 列候选清单：文件 / 问题 / 建议（每条一两行）
5. 问用户"想探索哪个"，逐项决策
6. 确定方向后记录结论（CONTEXT.md 或 ADR）

## 输出格式

- 候选: <文件> → <问题> → <建议>
- 决策: <选中的项 + 结论>

## 兜底

- 用户不感兴趣 → 记录摩擦点，结束
- 候选过多 → 只报 Top 3
