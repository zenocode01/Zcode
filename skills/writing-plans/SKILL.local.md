# writing-plans（本地精简版）

## 何时使用

- 需求已明确、任务多步、写代码前

## 工作流程

1. 列文件结构：每个文件一职责
2. 拆任务：每个任务以"可测的交付物"结尾
3. 每步一小动：写失败测试 → 跑红 → 最小实现 → 跑绿 → 提交
4. 计划头写清：目标 / 架构 / 全局约束
5. 每个任务写明：文件路径 + 输入输出
6. 自检：无 TBD/TODO 占位符、每个需求有任务对应

## 输出格式

- 计划: docs/plans/<日期>-<功能>.md

## 兜底

- 没有明确需求 → 先回 brainstorming
- 任务太大 → 拆小，保证每步 2-5 分钟
